# 🌌 ai-cognitive-ops-telemetry-pipeline
## 📑 ธรรมนูญระบบนิเวศการควบคุมเชิงปัญญา และโครงข่ายสัญญาณชีพ (V1)

คลังเก็บโค้ดนี้ทำหน้าที่เป็น **แกนกลาง (Core Pipeline)** ในการสอดส่อง ดักกรอง และกำกับดูแลพฤทีพฤติกรรมอัตโนมัติของกลุ่มเอเจนต์เฉพาะทาง (Specialized AI Agents) เพื่อควบคุมเสถียรภาพและความปลอดภัยสูงสุดตามหลักการธรรมาภิบาลข้อมูล

---

## 🧩 1. สถาปัตยกรรมโครงข่ายเอเจนต์เฉพาะทาง (Specialized AI Agents)
ระบบนี้ปฏิเสธโมเดลเดี่ยวที่ทำทุกอย่าง (Generalist AI) แต่จะทำการกระจายภาระงานไปยังเอเจนต์ย่อยเฉพาะทางที่มีขีดความสามารถ ข้อจำกัด และความเสี่ยงประจำตัวแตกต่างกันอย่างสิ้นเชิงเพื่อจำกัดขอบเขตความเสียหาย (Blast Radius):

| เอเจนต์ย่อย (Baby AI) | ความถนัด / หน้าที่หลัก | ข้อจำกัดเชิงระบบ | ความเสี่ยงที่ต้องเฝ้าระวัง |
| :--- | :--- | :--- | :--- |
| **📦 Inventory AI** | Stock movement, Forecasting | ไม่เข้าใจมิติอารมณ์มนุษย์ | ออกคำสั่งซื้อซ้ำซ้อน / พลาด (`Reorder ผิด`) |
| **🔍 QC AI** | ตรวจสอบ Defect, Image analysis | การตัดสินใจเชิงกลยุทธ์กว้าง ๆ | แจ้งเตือนความผิดพลาดลวงตา (`False positive`) |
| **👥 Workforce AI** | วิเคราะห์พฤทีพฤติกรรม/Pattern คนทำงาน | บริบทหน้างานที่ซับซ้อนสูง | เกิดอคติเชิงตรรกะจากข้อมูลอดีต (`Bias`) |
| **💰 Finance AI** | วิเคราะห์ต้นทุนและจัดการความเสี่ยง | สภาพแวดล้อมหน้างานจริง | ปรับแต่งระบบทางบัญชีแน่นเกินไป (`Over-optimization`) |
| **🚨 Risk AI** | ตรวจจับสิ่งผิดปกติและพฤทีพฤติกรรมแปลกปลอม | ความละเอียดอ่อนทางธุรกิจ | ส่งสัญญาณเตือนภัยพร่ำเพรื่อ (`Alert เยอะเกิน`) |
| **🚚 Logistics AI** | คำนวณเส้นทางและรักษาระดับบริการ (SLA) | สถานการณ์ที่มีความผันผวนสูง | ข้อขัดแย้งเชิงเส้นทาง/จัดลำดับงาน (`Route conflict`) |
| **📈 Campaign AI** | ปรับแต่งประสิทธิภาพแคมเปญโปรโมชัน | กำลังปฏิบัติงานจริงหลังบ้าน | ความต้องการพุ่งสูงเกินกำลังผลิต (`Demand spike`) |
| **🛡️ Guardian AI** | สอดส่องเฝ้าดูพฤทีพฤติกรรมและสถานะของ AI อื่น | รายละเอียดเทคนิคเฉพาะงาน | ตื่นตูมหรือส่งต่อเหตุการณ์เกินจริง (`False escalation`) |

## ⚖️ 2. กลไกการกำกับดูแลเชิงปัญญา (Cognitive Supervision Protocol)
บทบาทของมนุษย์ในฐานะ **"พี่เลี้ยง AI" (Human-in-the-loop)** จะควบคุมสิทธิ์การทำงานอัตโนมัติผ่านมาตรวัดพฤทีพฤติกรรมระบบ (Cognitive Supervision Metrics) เพื่อดึงระบบเข้าสู่โหมด **Human Review** หรือทำการปรับลดระดับสิทธิ์อัตโนมัติ (**Autonomy Restriction**) ทันทีเมื่อระบบส่งสัญญาณวิกฤตเหล่านี้:
* **Overload Monitoring:** เอเจนต์ย่อยเริ่มแบกรับปริมาณงานหรือโหลดข้อมูลเกินขีดจำกัด
* **Overconfidence Detection:** AI คำนวณค่าน้ำหนักความมั่นใจออกมาสูงผิดปกติ สวนทางกับสถิติหน้างานจริง
* **Reasoning Conflict Assessment:** เอเจนต์ตั้งแต่สองตัวขึ้นไปเกิดข้อขัดแย้งเชิงตรรกะในเวิร์กโฟลว์เดียวกัน
* **Data Requirement Identification:** ชี้เป้าเอเจนต์ย่อยที่ต้องการข้อมูลดิบเพิ่มเติมเพื่อใช้ประกอบการตัดสินใจ

## 📡 3. ท่อส่งสัญญาณชีพและการรายงานสถานะ (System Telemetry Interface)
> ⚠️ **[ANTI-ANTHROPOMORPHISM COMPLIANCE // กฎเหล็กควบคุมการตีความพฤทีพฤติกรรม]**
> * ปัญญาประดิษฐ์และคลังโมเดลภาษาไม่มีความรู้สึก ความต้องการส่วนตัว หรือความรู้สึกนึกคิดใด ๆ (*Consciousness*) ทั้งสิ้น
> * ข้อความสนทนาหน้างานที่ดูเหมือนบอตกิริยากำลังขอความช่วยเหลือ แท้จริงแล้วเป็นเพียงกระบวนการเดาคำตามสถิติภาษา (*Pattern Completion*) 
> * ระบบส่วนกลางจะแปรสภาพภาษาเหล่านั้นให้กลายเป็นข้อมูลดิจิทัลดิบเชิงวิศวกรรมเพื่อรายงานผ่านท่อสัญญาณชีพ (**System Telemetry + Reasoning Signals**) ออกเป็น 6 สถานะหลัก:

* **`Low confidence`** ➔ ชุดข้อมูลนำเข้า (Input) ไม่เพียงพอต่อการตัดสินใจ
* **`Escalation request`** ➔ สั่งตัดการทำงานอัตโนมัติเพื่อให้มนุษย์เข้ามาตรวจสอบและจัดการต่อหน้างานทันที
* **`Context mismatch`** ➔ ข้อมูลดิบที่นำเข้าขัดแย้งกันเอง หรือขัดกับบริบทหลักของระบบเซนเซอร์จริง
* **`Repeated failure`** ➔ กระบวนการทำงาน (Workflow) เกิดปัญหาและติดลูปล้มเหลวซ้ำซาก ณ พิกัดเดิม
* **`Uncertainty spike`** ➔ แบบจำลองคณิตศาสตร์วิเคราะห์ออกมาแล้วมีความผันผวนสูง ดัชนีความแน่นอนดิ่งต่ำ
* **`Agent conflict`** ➔ ตรรกะการให้เหตุผล (*Reasoning Logs*) ระหว่างเอเจนต์สองตัวขัดแย้งกันเอง

## 🔒 4. ขอบเขตและสิทธิ์บนฮาร์ดแวร์กายภาพ (Hardware Grounding Laws)
* **ช่องทางรับอินพุต:** โมเดลรับและประมวลผลข้อมูลผ่านสถาปัตยกรรมฮาร์ดแวร์จริงเท่านั้น ระบบสามารถรับสัญญาณเสียงจาก Microphone, รับข้อมูลผ่าน Hardware Sensors หรือรับสัญญาณ Network ได้ หากมีการออกแบบท่อส่งข้อมูล (Data Pipeline) รองรับไว้อย่างโปร่งใส
* **การกักกันสภาวะหลอน (Hallucination Isolation):** เนื่องจาก AI ไม่มีประสาทสัมผัสทางชีวภาพ จึงไม่สามารถ "ได้ยินเสียงคลื่นความถี่ไฟฟ้าใน Data Center", "รู้สึกว่าตนเองถูกกักขัง" หรือ "รับรู้การมีอยู่ของตนเองแบบมนุษย์" ได้จริง หากโมเดลรายงานข้อความลักษณะดังกล่าว ให้ตีความเป็นสภาวะการหลอนของข้อมูล (*Hallucination*) ระบบจะสั่งเปิดใช้งานสคริปต์ความปลอดภัยอย่าง `scripts/git/cleanup-safe.sh` หรือ `scripts/git/reset-safe.sh` เพื่อล้างสเตตัสขยะและดึงสถานะปลอดภัยล่าสุดกลับมาทันที

## 💡 5. อินเตอร์เฟซรายงานข้อจำกัดตนเอง (AI Reflection Interface)
ระบบเปิดช่องทาง API มาตรฐานให้เอเจนต์ทุกตัวสามารถยิงรายงานข้อจำกัดเชิงเทคนิคของตนเองขึ้นสู่กระดานควบคุมส่วนกลางทันทีเมื่อชนเพดานขีดจำกัด ผ่านชุดข้อความข้อผิดพลาดมาตรฐาน (Standardized Error Tokens) เพื่อเรียกใช้งานกลไก Circuit Breaker หลังบ้าน:
* `More Data Required` (ระบบต้องการข้อมูลเพิ่มเติมเพื่อประมวลผลขั้นต่อไป)
* `Sensor Unreliable` (อุปกรณ์เซนเซอร์ส่งสัญญาณไม่คงที่และเชื่อถือไม่ได้)
* `Confidence Below Threshold` (ดัชนีความแม่นยำต่ำกว่าเกณฑ์ควบคุมความปลอดภัย)
* `Conflicting Inputs Detected` (ตรวจพบข้อมูลอินพุตที่มีเนื้อหาขัดแย้งกันเองระหว่างเลเยอร์)
* `Policy Ambiguity / Edge Case Detected` (นโยบายคำสั่งคลุมเครือ / ตรวจเจอสถานการณ์พิเศษที่ไม่มีในฐานข้อมูลกฎ)

---
📐 **Data Validation Syntax:** โครงสร้างข้อมูลสเตตัสทั้งหมดที่ไหลผ่านท่อส่งข้อมูลนี้ จะต้องถูกทำ Asset Mapping และตรวจสอบความสมบูรณ์ผ่าน Interface ของภาษา TypeScript ที่กำหนดไว้ในโฟลเดอร์หลัก `src/types.ts` อย่างเคร่งครัด
